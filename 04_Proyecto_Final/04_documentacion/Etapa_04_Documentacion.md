# Proyecto Final — 04 Documentación

> Un proyecto sin documentación es un proyecto que nadie puede usar.

## 🎯 Objetivo

Documentar todo el proyecto para que otra persona pueda entenderlo, instalarlo y usarlo.

## 📖 Qué hacer aquí

1. **Manual de instalación:** pasos para crear la base desde cero
   (orden de ejecución de scripts, motor requerido).
2. **Manual de uso:** cómo correr las consultas y qué responde cada una.
3. **Decisiones de diseño:** justificar normalización, índices, vistas, roles.
4. **Lecciones aprendidas:** qué fue difícil, qué errores cometiste
   y cómo los resolviste.
5. (Opcional) capturas de resultados de las consultas clave.

## ✅ Tareas

- [ ] `01_manual_instalacion.md` — pasos exactos para reproducir la base.
- [ ] `02_manual_uso.md` — guía de las consultas y reportes.
- [ ] `03_decisiones_diseno.md` — por qué elegiste cada diseño (2 páginas máx.).
- [ ] `04_lecciones_aprendidas.md` — reflexión de todo el camino de aprendizaje.

## 📦 Entregables

- `01_manual_instalacion.md`
- `02_manual_uso.md`
- `03_decisiones_diseno.md`
- `04_lecciones_aprendidas.md`

> 🏆 **Cierre:** cuando la documentación esté lista, actualiza el `README.md`

## 📂 ¿Qué debe colocar la persona en esta carpeta?

Todo el **trabajo realizado**, en cualquier formato:

- 🖼️ **Imágenes** (`.png`, `.jpg`): diagramas, capturas de pantalla de resultados.
- 📄 **Word** (`.docx`): resúmenes, informes o explicaciones.
- 📊 **Excel** (`.xlsx`): tablas de datos, cálculos o comparativas.
- 🗄️ **Base de datos** (`.db`, `.sqlite`): la base de datos trabajada.
- 💾 **Consultas y scripts** (`.sql`): ejercicios resueltos y scripts creados.

> Regla de nombres: un archivo por actividad, con nombre descriptivo
> (ej: `diagrama_er_final.png`, `practica_joins.sql`, `resumen_actividad.docx`).
